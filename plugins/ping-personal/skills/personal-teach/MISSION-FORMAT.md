# MISSION.md Format

`MISSION.md` lives at the workspace root. It records *why* the user is learning the topic. Every
teaching choice traces back to it: what to teach next, which sources, which exercises.

## Template

```md
# Mission: {Topic}

## Why
{1-3 sentences. The concrete goal. What changes in the user's work when they have this skill?
Push past "to understand X" to the real outcome.}

## Success looks like
- {Something specific the user will be able to do, that someone else could observe}
- {Another one}

## Constraints
- {Time, budget, commitments, learning preferences}

## Out of scope
- {Nearby topics the user does not want to chase now}
```

## Rules

- **One mission per workspace.** Two unrelated topics are two workspaces.
- **Concrete over abstract.** "Explain context engineering with three examples from my own work in an interview" beats "learn context engineering".
- **Push back on vagueness.** If the user cannot say why, ask before writing anything. A bad mission is worse than none.
- **Revise when reality shifts.** When the goal moves, update this file.
- **Keep it short.** Past one screen, it has become a plan, not a compass.
