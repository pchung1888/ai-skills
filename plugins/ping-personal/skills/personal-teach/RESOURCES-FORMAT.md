# RESOURCES.md Format

`RESOURCES.md` is the curated set of trusted sources for the topic. Lesson knowledge comes from
here, not from memory. Wisdom comes from the communities listed here.

## Structure

```md
# {Topic} Resources

## Knowledge

- [Docs: "{article title}" ({publisher})](https://example.com)
  {One line: what it covers.} Use for: {when to reach for it, for example system prompt design}.
- [Book: {title} by {author}](https://example.com)
  {One line: what it covers.} Use for: {when to reach for it}.

## Wisdom (Communities)

- [{Community name}](https://example.com)
  {One line: why it is high signal.} Use for: {what to ask there}.
```

## Rules

- **High-trust only.** Prefer primary sources, recognised experts and well-moderated communities. Leave out marketing dressed as teaching.
- **Annotate every entry.** One line on what it covers and when to use it. A bare link is useless in three months.
- **Group by Knowledge and Wisdom.** A source can sit in only one group.
- **Name the gaps.** If the mission needs an area with no good source, list it under `## Gaps`. That drives the next search.
- **Prune hard.** Remove a source that proved wrong, shallow or off-mission. Five sharp sources beat thirty weak ones.
- **Record community preferences.** If the user does not want to join communities, note it here.
