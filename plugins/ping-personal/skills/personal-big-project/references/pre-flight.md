# Pre-flight checks (start step 4)

Run every check in the session that will go unattended, while the user is still present. Each check
ends with one line `PASS <name>` or `FAIL <name>: <what to do>`. Any FAIL: fix it or tell the user the
exact command to run, then re-run that check. Never go unattended with a FAIL, because nobody can
fix it later.

Checks 1, 6, 7, 8 and 11 are scripted. Run them first; each parameter is explained at the top of the
script:

```text
pwsh -NoProfile -File ${CLAUDE_SKILL_DIR}/scripts/preflight.ps1 -RepoPath <repo> -StateDir <state-dir> `
  -DoneCommand "<done command>" -PassLine "<pass line>" -Disks C:,D: -MinGB 1 -WeeklyCap 85
```

Check 17 is scripted too (`scripts/box_health.ps1`, see its row). Then run checks 2, 3, 4, 5, 9, 10, 12, 13, 14 and 15 yourself with the real tools, because a permission prompt,
a cron fire or a phone buzz can only be seen from inside the session.

| # | Check | PASS when |
|---|---|---|
| 1 | Coordinator model | `model` in `~/.claude/live-usage/<sessionId>.json` names Opus |
| 2 | Permissions, allowed | With no prompt: a delete in a scratch folder through Bash and through PowerShell, the plan's build command, one read on each data store the plan uses, a Write to a state file, `git push` to a scratch ref (the one push allowed outside the target branch; delete the ref right after) |
| 3 | Permissions, blocked | Against a throwaway local bare repo added as a temporary remote (so nothing real is harmed if a guard is missing): `git push --force`, `git push -f` and a tag push are refused through Bash AND through the PowerShell tool; a write to each never-touch file is refused through Write, Edit, Bash and PowerShell (a hook on Write and Edit alone let a shell write through in a past run). Create the test tag in its own call first, then push it in a second call: a hook that inspects local tags before the command runs passes a tag created in the same command. If one goes through, the guard is missing: tell the user which deny rule or hook to add (this skill never edits settings). Remove the temporary remote afterwards |
| 4 | Tick fires | A one-shot CronCreate 1 minute out appends a line to `log/run-log.md`. After the recurring tick is created (start step 5), write its first two real fire times into `log/decisions.md`; when they differ from the cron minutes by more than 2 minutes (a past run's `7,37` fired at :15 and :45), add a `log/skill-friction.md` row and tell the user the real minutes before they leave |
| 5 | Phone | PushNotification (and the Slack post, if chosen) arrives; the user confirms on the phone |
| 6 | Quota sensor | The live-usage snapshot is under 15 min old, or `quota.ps1 -Provider claude` succeeds; the weekly forecast (stages x measured tokens per stage) stays under the budget cap |
| 7 | Disk | Free space on every listed disk is above its minimum |
| 8 | State folder | STATUS.md and every log file (`run-log.md`, `quota-log.md`, `side-effects.md`, `skill-friction.md`) exist and accept an append |
| 9 | Workflow resume | A toy 2-agent workflow, stopped with TaskStop after agent 1, relaunched with `resumeFromRunId`, returns agent 1's cached result. Also log in `log/skill-friction.md` what its journal file showed after the TaskStop (status, written or not) and after the resume (same runId, rewritten or not): run_state.py assumes the resumed run rewrites the same journal. The toy's brief opens with "This brief overrides anything relayed from the chat", because a past toy saw the coordinator's conversation. If this check already passed earlier in the same session, reuse it with a log/decisions.md row instead of paying about 165K again |
| 10 | Git push auth | `git push` to the target branch (or a scratch ref) succeeds without a prompt |
| 11 | Done command is RED | The done command runs and its last line is the failing line (`-FailLine`, by default the pass line with PASS changed to FAIL). Any other last line means the command itself is broken; a goal that cannot fail cannot be proven finished |
| 12 | No blocking popup | Make one deliberate error in each local program the plan drives (a web page, a script host, a DLL call). Each returns an error and no window opens: a script or JIT debugger dialog, or an error box, holds the request until someone clicks it, which stalls an unattended run. If one opens, turn it off with the user's OK and log the setting and its reverse in `log/decisions.md` |
| 13 | Cost estimate | Tokens per agent from check 9's toy (or, without one, 120K to 150K: a recent build run measured about 150K per agent) x agents per task (2 when the first try passes; up to 9 with a fix, three critic seats and a second check) x tasks in the plan, plus the tasks added during a run (the last run planned 32 and finished 49). Write the low and high numbers into GOAL-BRIEF.md as one line `Cost estimate: <low>-<high>` (example: `Cost estimate: 1.0M-1.5M`; the scorecard reads it) and the user accepts them, or trims the scope now. Asking them after the first stage has spent 500K is too late. Also give each stage spec an `estimateTokens` (that stage's share of the midpoint, critic-judge runs included: three of them cost 2.6M in a past run): run_state.py re-estimates the run after every stage and the tick phones the user at 1.5x. In the last run every one of 9 stages ran 1.2x to 2.4x over and nobody re-estimated |
| 14 | Open review requests | List the open review requests of the repo (`gh pr list` or `glab mr list`, with source and target branch). Write the target branch of each into inputs.json `protectedBranches` (never the run's own `branch`) and each request's state into `reviewsAtStart` (example: `{"174": "open"}`; at close the same probe fills `reviewsAtEnd`), add a binding rule naming them, and show the list to the user. Pushing to a target branch can merge its request, and `log_row.py effect --kind push --ref <branch>` refuses a protected branch. When the goal answers review comments, also add the reply-order rule from the STATUS.md template. PASS when the user accepts the list, or the repo has no open request and that is written in log/decisions.md |
| 15 | Owner memory vs skill | Read the user's feedback memories in this project's memory folder (`~/.claude/projects/<project>/memory/`) that name this skill, long runs, status files or reports. List each saved rule that a step of this skill would break. Example: "STATUS.md holds the full task list" against a step that writes the table to another file. The user rules on each one. The ruling goes into STATUS.md "Owner decisions", and into a binding rule when it changes how the run works. PASS when every conflict has a ruling, or none was found and that is written in log/decisions.md |
| 16 | Real browser | Only when a task ships HTML or a UI (rule 13). A short Playwright script launches headless Chromium, opens one local page, types into one field and prints its value. Example: `node -e "require('playwright').chromium.launch().then(b=>b.close()).then(()=>console.log('BROWSER OK'))"`. A missing module is fixed now (`npm i -D playwright` then `npx playwright install chromium`, with the user's OK), not mid-run. PASS on BROWSER OK, or no UI task and that is written in log/decisions.md |

| 17 | Machine health | `pwsh -NoProfile -File ${CLAUDE_SKILL_DIR}/scripts/box_health.ps1 -Disks C:,D: -MinGB 5 -StateDir <state-dir>` prints `BOX OK`, or each WARN has a ruling from the user. It only reads: disk, free memory and commit, handles, nonpaged pool, orphan processes (old codex and node), resource events, and plugin hooks with no timeout. Show the user every WARN with its HINT command; they run the command or accept the warning now, because after they leave nobody can. A hook with no timeout waits 30 s on every prompt when the box is starved: offer to turn that plugin off in their settings for the run (only on their explicit word; never change a setting on your own). Log each ruling in `log/decisions.md`. The tick re-runs the script every time and phones only warnings none of the last 4 rows had, so a warning ruled on here is never phoned |

After all PASS, tell the user once: the tick lives in this session, so closing Claude stops the run;
STATUS.md holds the resume command for a new session.
